# 蓝图路线图与待办

只保留尚未完成、符合可携带方案与证据定位的长期项；具体实施与验收属于当前方案。已完成里程碑和退场沿革见 [历史索引](../history/index.md)。

## 未完成长期项

- [ ] 补真实宿主行为及冷启动接续证据：区分安装、可发现、实际执行与交接成功，不以模拟会话代替宿主验证。
- [ ] 扩展文件合规检查之外的行为覆盖，包括 checkpoint、显式 finalize 和必要的 knowledge_sync；复用现有协议与宿主，不新增执行引擎。
- [ ] 让外部宿主按 [接入文档](../../docs/host-onboarding.md) 独立确认能力与最低边界，并把实际发现反馈到已有文档和测试。
- [ ] 完善 Verifier evidence 的规范化和跨审查者解释：只在真实互操作问题出现时推进 Protocol 的 draft 部分，不新增默认审查流程。
- [ ] MCP 持久注册扩展证据：Qoder / Claude / Copilot 沿用同一最小契约验证；Claude 会话级只读证据不等于持久注册。打包、doctor 和自动注册仍待重复需求。
- [ ] Skill 打包与双语资产治理：保持单一来源、安装产物一致性及资源路径可达，避免增加宿主维护分叉。
- [ ] 在真实使用中核对首次上手步骤、必读材料和重复维护负担；只修已经观察到的摩擦，不先建指标或评测平台。

## 明确延后项

| 项 | 重访条件 |
|---|---|
| stale stub 自动建议重装或降级 | 已有诊断仍不能解决重复发生的问题，且用户选择 opt-in 修复 |
| blueprint 更细粒度索引、history 聚合视图 | 当前索引反复无法定位真实方案或证据 |
| 非 CLI 宿主的交互表单 | 出现明确宿主需求和可验证的本地能力 |
| 偏好自动归纳、知识提炼 | 人工保留政策遇到可复现瓶颈，并有明确授权与验证边界 |

## 选择工作时

先核对现有代码、协议与证据，再确定最小写集；区分契约变更和实现步骤。涉及主体、状态、checkpoint、receipt 或归档边界时，核对 [设计预算](./design.md#削减预算与持久化边界) 与 [Protocol](./protocol.md)，必要时补 ADR。不要为沿用历史编号而引入已停止的 runtime 路线。
